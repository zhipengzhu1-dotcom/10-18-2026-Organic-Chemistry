# 3D: the molecule card, orbitals, Explore in 3D

## One engine

Every 3D view is the three.js/R3F card in `site/src/molecule/` (`MoleculeCard.tsx`). Explore in 3D (`site/src/explore/ExploreIn3D.tsx`) opens the same card in a `<dialog>`; orbitals draw inside it as children. Build new 3D features into this card. 3Dmol.js was removed; the Lesson specs that still name it are out of date.

- Scenes stay 2D (SVG). Scenes take no Student input and the Remotion video path has no WebGL (ADR 0001), so a "3D model" Scene is an SVG drawing and anything rotatable goes on the card. A spec "orbital Scene" (`orbital-viewer`, `ethylene-sigma-pi`, …) is the card with `orbitals:`.
- One card shows one molecule data file at a time. Two molecules in one frame (NH₃ + BF₃) are a pipeline `pair` data file (`pipelines/orbitals/compute.py`), not a client-side feature.

## Authoring `molecule:`

The fields and their comments live in `content/src/step-types/fields.ts` (`moleculeFields`, `moleculeUse`); the resolver is `content/src/molecule-use.ts`.

- `molecule: <id>` adds only the Explore button. `{ id, card: true, … }` adds the inline card. Rotate-and-identify always shows the card. A Check Step inherits its Problem's molecule.
- Before adding a card option, read `moleculeFields`: `label`/`labels`, `pageSheet`, `dipoles`, `orbitals`, `plane`/`planes`, `measure`, `zoom`, `toggle`/`toggleLabel`/`autoplay`, `orbitalLabels`, `tapMeasure` already exist. `pageSheet` is the *screen* plane (snaps to the page view); `plane` is a molecular plane that turns with the molecule.
- A toggle keeps the card's rotation across entries with the same `id`, so σ | π | both is one molecule listed three times with different `orbitals`.
- `card: true` merges the card's cited values into the Step's Source note.

### Answer leaks

The card and Explore show real geometry, and their Source note prints cited values at full precision. Put a molecule on the Explain/Wrap Step next to a geometry question, never on the Step whose answer is that geometry value (e.g. "what is the H–C–H angle?"). An auto `measure` is fine when the answer is an order, not a value. For orbitals named only A/B, `orbitalLabels: hide` serves meshes by hash (`/orbitals/m/<sha16>.glb`, `site/src/lib/orbital-meshes.ts`, `blindMesh`) so file names don't give the answer away.

## Start views (`content/subjects/organic/views.yaml`)

- Atom indices are 0-based in the data file's atom order: CCCBDB's order for experimental files, SMILES order then H's for computed ones. Open the JSON to count.
- Prefer `plane` + `front` + `up` for "as drawn on the page" views; `look` for end-on views.
- No `view` means `DEFAULT_VIEW` (`rotate: [15, 70, 0]`): CCCBDB puts planar molecules in the yz plane, which is edge-on to the screen.
- Every new view gets a projection test asserting which atoms end up where (see `content/test/lesson-03.test.ts`, `lesson-04.test.ts`, `site/src/lib/lesson-08.test.ts`). True orthographic geometry can stack a wedge/dash pair on top of each other (the `ps1-q2b-*` views); the 2D drawings separate them.

## Orbitals on the card

- Reference: `orbitals: [<orbital data file>/<orbital id>]`, needs `card: true`. The orbital set must be computed on the same molecule data file (L8 uses the `*-b3lyp` files, L4 the experimental ones); the build rejects a mismatch.
- Styles: `sigma`/`pi` (L4: colour = kind, hatch = − sign) and `phase` (L8: + blue solid, − orange hatched). Phase is never colour alone.
- Lobes draw after atoms (`depthWrite: false`, higher `renderOrder` than atoms and plane sheets), front faces only, so the pipeline's winding gate matters (see `pipelines.md`).
- Orbital cards usually need `zoom` 1.4–1.6: the default fit is for the true-scale molecule at any rotation, which leaves lobes small.
- e2e hook: `data-orbitals="loading|drawn"` on `.molecule-stage`.

## Loading and fallbacks

- `MoleculeCanvas.tsx` (three + R3F) and `OrbitalLobes.tsx` (GLTFLoader + meshes) are lazy chunks, outside the first-load JS budget (`site/src/lib/js-budget.ts`). Keep every `three` import inside a lazy module.
- `frameloop="demand"`: nothing spins, so reduced motion has nothing to stop on the card itself.
- Without WebGL2 (`canDrawWebGL()`), the card shows the SVG still (`MoleculeDrawing.tsx`) at the start view; picking, measuring, Describe and the Source note still work and the Step finishes. The still shows orbital sign labels and chips but no lobe shapes.
- Atoms use `MeshMatcapMaterial` on `/matcaps/studio.webp` (rendered by Blender, `pipelines.md`), tinted with cited Jmol colours from `elements.yaml`. Radii are cited vdW radii; ball-and-stick is vdW × `BALL` (`layout.ts`). Every element shown needs `<El>.colour` and `<El>.vdw` in `elements.yaml` (boron uses Mantina 2009, since Bondi has none).
- Colours (#118): the stage ground is a pale blue wash on paper (`.molecule-stage`), so white hydrogens never sit on white; overlay text is pen ink (`--at-blue`, `--at-orange`) on a paper halo. Bonds and plane sheets read `--at-ink-muted`, lobes `--at-blue-fill`/`--at-orange-fill`, from the page through `site/src/molecule/token.ts` (three.js takes no CSS var).

## Phone fit

The card fills the Step's spare height and can shrink to a ~96 px stage on long Steps. Card Steps hide the separate Explore button on phones (the card is the same viewer), drop the prompt visually while a Hint shows, and the Lesson-end screen hides a Wrap card. Rules live in `site/src/styles/global.css` and `site/src/components/structure.css`.
