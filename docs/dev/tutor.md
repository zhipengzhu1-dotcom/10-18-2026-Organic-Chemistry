# Tutor (dev only)

Spec #104. Runs under `pnpm dev` only, on the owner's signed-in `claude` command. The build carries none of it (`pnpm budget:js` fails if it does).

## Modules (`site/src/tutor/`)

- **Tutor context** (`context.ts`, tested): the only path Step data takes to the model. Input: the page Lesson (no Answer key), the Screen's `index`/`total`/`tries`/`feedback`/`canContinue`/`done` (`TutorScreen`, never `screen.step` or `state`), the Student's draft and the stage. Feedback text passes only for a Hint or a shown push, or once the Step can continue. All text goes through `plain()`.
- **Tutor route** (`route.ts`, tested): Connect middleware mounted at `TUTOR_PATH` by the `tutorRoute()` Vite plugin (`apply: "serve"`, registered in `site/astro.config.mjs`). Loopback only (`isLoopback`, unit-tested: IPv4 127/8, `::1`, IPv4-mapped 127/8; the LAN test skips on a machine with no LAN address); model and effort allowlisted (default Sonnet 5.5 · low); `claude -p` in an empty temp folder with no tools, settings, MCP or session, `--json-schema`, `stream-json`; Student and history text escaped in `<student>`/`<tutor>`, history in `<conversation>`, the context in `<step>`. `ASTRATRON_TUTOR_CLAUDE` replaces the binary (tests use `test/fake-claude.mjs`; `FAKE_CLAUDE_MODE` scripts slow, non-zero exit, signed-out and malformed runs, `FAKE_CLAUDE_ACTIONS` the stage actions, `FAKE_CLAUDE_ANSWERS_WITH` the model id it reports; it logs its pid). Limits: 2 running (the third gets an immediate `error` "busy"), killed after 120 s, body over 64 KB → 413 with one NDJSON `error` line ("too long") without running `claude`, message cut to `MAX_MESSAGE` (2000), last `HISTORY_TURNS` (10) turns. A request that goes away mid-reply (`res` closes unfinished) kills its `claude` and frees the slot. Every failure (busy, timeout, missing binary, signed out, non-zero exit, broken stream) is one `error` line with a readable message. The meta line's model is the allowlist label whose id the reported one contains (`claude-haiku-5-5-20261001` → Haiku 5.5), else the raw id.
- **Conversation flow** (`flow.ts`, tested): `enterStep` gives the thread on a new Step (only the scripted intro until the Student has spoken, so a resumed Lesson starts at its current Step; after that a divider plus the intro). `chipsFor` picks the suggestion chips from the Step's type, `canContinue` and whether a Scene is on the stage. `historyOf` is what a question carries (no dividers, error lines or the live reply; last 10), `patchLast` updates the reply being written, `digitRuns` splits text so the panel draws each digit run (with sub/superscripts, ⁺/⁻, decimals) in `.data`.
- **Contract** (`contract.ts`): `TUTOR_PATH`, `PANEL_CLASS`, `MAX_MESSAGE`, `HISTORY_TURNS`, `lineSplitter` (the NDJSON line splitter both the route and `stream.ts` use), the request and the NDJSON events (`reply`… `done` | `error`).
- **Tutor panel** (`TutorPanel.tsx` + `tutor.css`, by hand): the Ask button in the top bar and the panel, portalled to `<body>`: a sheet below 720 px, a side panel from 720 px (the player pads right while it is open, via `html[data-tutor="open"]`). Kept mounted and `inert` when closed so it can fade/slide. Finished replies go to a polite live region once (the streaming text isn't announced). Stream reading: `stream.ts` (tested with a stubbed `fetch`; an NDJSON body on a non-200, such as the 413, is read like any other, so its `error` shows as a thread error line). Stage reading: `stage.ts`. ⌘K / Ctrl+K opens it with the field focused and no slide or fade (`data-instant`); Esc closes. The sheet closes on a swipe down its header (pointer events, not on its buttons or picker): it follows the finger (`data-dragging` turns the transition off) and closes past 30 % of its height or on a downward flick over 0.5 px/ms, else settles back; under reduced motion it stays put and closes by fading; from 720 px there is no swipe. Error lines are marked "! Tutor problem" with a dotted border, not by colour alone; the panel stays usable after one. Thread text and dividers put digits in `.data` via `digitRuns`; the meta line and the picker are wholly in the data face (an `<option>` can't hold a span).
- **Paper look** (#122, `tutor.css`): the sheet and panel are paper with a pen edge (`--at-pen` ink, top on the sheet, left on the side panel). Turns are hand-drawn boxes (`--at-wobble-2`): the Student's on a light blue tint in a dashed line on the right, the Tutor's on paper with a violet rule on the left, so side, edge and name tell them apart without colour. Ask and the chips are the shared pen button (`.btn`; chips on `--at-wobble-pill`) in blue ink, and close is the player's ✕ circle (`.pen-circle`); `tutor.css` only overrides size, face and colour, and `tutor.spec.ts` checks they match Send and the player's ✕. Opening slides and fades at `ui` (200 ms), closing at `exit` (150 ms): within the spec's 300 ms UI rule.
- **Stage moves** (#107): the schema asks for `actions` (≤4); the route's `stageActions` (tested) drops unknown types, off-stage atoms, atoms on the `LOOK_ONLY` "target (look only)" drawing and a `set` with no control, clamps `at` to 0..1 and `value` to the control's range. On the page, `stage.ts` reads the stage (`readStage`: Scene, control with label/min/max/value, labelled atoms with their drawing) and carries the actions out (`moveStage`) by pressing the Scene player's buttons and sliding Scrub or the control (native value setter + `input` event, so React and the live text update), or pressing a stepper's − / + a frame apart until its `data-value` matches. Both sides index the same atom list (`atomsOnStage`: visible `.structure text.atom` in `.player-body`, outside Scene frames, which redraw every frame). The panel snapshots the stage when it sends and `moveStage` rings atom *i* only if `ringable` (tested): the atom there now has the label and drawing the snapshot had, and isn't on the target. Rings (`.tutor-ring`, #122: a violet marker band under a violet pen circle + four crosshair ticks, the ticks being the non-colour cue that tells it from Tap's ✓ picked ring; styled in `tutor.css`, not `structure.css`) are appended to the drawing's SVG; they clear on a new highlight, `clear`, a Step change or unmount. A drawing that re-renders its SVG (a Draw-arrows push) drops them.
- **Settings** (#106): the route's `GET` returns `TutorChoices` (models, efforts, default pair); the panel builds its picker from it and sends the chosen `model`/`effort` with each question. `settings.ts` remembers the pair (`at-tutor-pick`, `model|effort`: `pairOf` writes it, `parsePick` reads it, tested; falling back to the default when the route no longer offers it) and the on/off switch (`at-tutor-switch` = `off`), reads and writes wrapped in try/catch. Each finished reply shows `done`'s model, effort and seconds. Off leaves only the header's switch, unchecked (`.tutor-wake`, labelled "Tutor"), in the Ask button's column: no panel, no portal. A text label there pushes the story bars out at 390 px.
- **Build check** (`absent.ts`): run by `pnpm budget:js`.

Browser test: `site/e2e/tutor.spec.ts` (#114) runs the design gate's type rules on the open panel, on the dev server (`docs/dev/testing.md`).

## Gotchas

- In current Chromium `scrollIntoView` returns a Promise: an arrow-bodied `useEffect` that returns it crashes React. Use block bodies.
- The first open after a dev-server start can reoptimise deps and reload the page.
